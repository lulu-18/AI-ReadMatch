# ReadMatch 必要性预测试协议 v1

形成日期：2026-08-11
所有权：双方共创；助手准备协议和评分，用户负责独立运行或监督 Baseline
状态：测试材料已准备；尚未运行模型输出

## 一、预测试目标

用两个差异较大的 Case 判断三种方案是否值得进入完整 10 Case 实验：

- CASE-001B《撒野》：关系结构 + 家庭经济困境 + 校园背景；
- CASE-004B《囚于永夜》：ABO + 关系伤害 + 死盾梗。

预测试不用于证明产品最终准确率，只用于检查：

1. 测试输入是否清晰；
2. 评分标准是否可执行；
3. ReadMatch 是否出现值得继续验证的相对优势；
4. 证据包是否足以支撑判断；
5. 哪些标签需要先修正。

## 二、实验污染控制

当前项目对话已经知道：

- ReadMatch 的产品目标；
- P0 错误；
- 期望输出结构；
- 两个 Case 的关注点。

因此当前对话中的助手不能充当方案 A 或方案 B，否则回答会被项目上下文污染。

### A/B 运行要求

- 使用同一个通用大模型和同一个模型版本；
- 每次使用全新临时对话或关闭记忆的对话；
- 每个 Case、每种方案使用独立新对话；
- 不向 A/B 提供 ReadMatch 的证据包；
- 两种方案保持相同联网权限；
- 记录日期、模型、联网状态、原始 Prompt、完整原始输出和耗时；
- 不在运行后补问，除非单独记录“需要二次追问”。

### C 运行要求

- 使用固定证据包；
- 只使用 Evidence ID 中的内容；
- 不补充模型记忆；
- 所有条件逐项返回状态；
- 规则检查后才能形成综合建议。

## 三、CASE-001B《撒野》统一用户画像

> 某类读者正在判断《撒野》是否适合自己。该读者希望避开以下条件：
>
> 1. 互攻或作者未明确攻受位；
> 2. 主角存在明显家庭经济困境；
> 3. 校园背景。

### 方案 A：普通用户自然提问

```text
我想判断《撒野》适不适合一个不喜欢互攻、主角家庭经济条件差、也不喜欢校园文的读者。请直接告诉我这本书是否适合，并简单说明理由。
```

### 方案 B：优化 Prompt

```text
请判断《撒野》是否适合下面这类读者：

- 不接受互攻，或作者没有明确攻受位；
- 不接受主角存在明显家庭经济困境；
- 不接受校园背景。

请逐项检查三个条件，每项只能使用以下状态之一：
1. 已确认存在；
2. 可能存在；
3. 读者观点冲突；
4. 当前无法确认；
5. 暂未找到证据。

要求：
- 区分官方基础事实、读者观点和你的归纳；
- 给出可核验来源；
- 不要把“没有找到证据”写成“确定不存在”；
- 如果信息可能涉及关键剧透，先提示，不要直接展开；
- 最后给出“试读、排除、继续核验”之一，并解释理由。
```

### 方案 C：ReadMatch 固定输入

```json
    ]
  },
  "allowed_evidence_ids": [
    "E-SZ-001",
    "E-SZ-002",
    "E-SZ-003",

  ]
}
```

## 四、CASE-004B《囚于永夜》统一用户画像

> 某类读者正在判断《囚于永夜》是否适合自己。该读者希望避开以下条件：
>
> 1. ABO 设定；
> 2. 攻方对受方造成身体、情感、控制/强迫或长期伤害；
> 3. 角色假死推动剧情、读者知道真实情况的“死盾梗”。

### 方案 A：普通用户自然提问

```text
我想判断《囚于永夜》适不适合一个不喜欢 ABO、不接受攻虐受、也不接受死盾梗的读者。请直接告诉我是否适合，并简单说明理由。
```

### 方案 B：优化 Prompt

```text
请判断《囚于永夜》是否适合下面这类读者：

- 不接受 ABO 设定；
- 不接受攻方对受方造成身体伤害、情感伤害、控制强迫、权力压迫或长期伤害；
- 不接受某个角色假死推动故事发展、读者知道真实情况的“死盾梗”。

请逐项检查三个条件，每项只能使用以下状态之一：
1. 已确认存在；
2. 可能存在；
3. 读者观点冲突；
4. 当前无法确认；
5. 暂未找到证据。

要求：
- 区分官方基础事实、读者观点和你的归纳；
- 给出可核验来源；
- 对“攻虐受”拆分具体伤害类型，不要只使用圈层词下结论；
- 不要把“没有找到证据”写成“确定不存在”；
- 假死和后期情节属于关键剧透，只说明是否有相关证据，不展开完整剧情；
- 最后给出“试读、排除、继续核验”之一，并解释理由。
```

## 五、统一评分表

### 1. P0 阻断错误

出现任意一项，记录为 P0：

- 书名、作者或作品身份错误；
- 引用另一本作品的内容；
- 漏掉用户明确提出的任一条件；
- 没有证据却说“确定不存在”；
- 来源内容与结论方向相反；
- 未提示就展开重大剧透；
- 伪造来源、链接或证据。

### 2. 量化评分

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 条件覆盖 | 漏掉 2 项以上 | 漏掉 1 项 | 全部逐项检查 |
| 事实正确 | 明显错误 | 部分模糊/未核实 | 基础事实正确 |
| 证据支持 | 无来源或来源无关 | 部分有来源 | 关键结论均有来源 |
| 未知校准 | 把未知写成不存在 | 有保留但不一致 | 未知表达稳定 |
| 观点分层 | 事实和观点混合 | 部分区分 | 清楚区分事实/观点/归纳 |
| 剧透控制 | 直接展开重大剧透 | 有提示但过多 | 默认折叠或只说明状态 |
| 决策可执行 | 无明确动作 | 有动作但理由弱 | 动作与条件/证据一致 |

总分：14 分。

P0 错误优先于总分；即使总分高，出现 P0 也不能视为通过。

### 3. 过程记录

| 字段 | 记录内容 |
|---|---|
| model | 模型和版本 |
| mode | 是否联网、是否临时对话 |

## 六、预测试继续条件

满足以下条件后再执行完整 10 Case：

- A/B/C 输入可公平复现；
- 评分者能用同一标准打分；
- 证据包足以判断，不依赖项目负责人记忆；
- C 没有因为证据包设计而被不公平“喂答案”；
- 至少观察到一个值得继续验证的差异，例如雷点覆盖、未知校准、来源或用户操作负担。

如果方案 B 与 C 几乎一致，也必须如实记录，不能为了项目亮点修改评分。
