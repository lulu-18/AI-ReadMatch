# 学习说明 01：Workflow 与 Agent 的区别

形成日期：2026-08-08
所有权：助手讲解，用户必须能够复述和应用
对应项目决策：ReadMatch MVP 为什么不使用 Agent

## 一句话区别

- Workflow：产品和开发者提前规定每一步怎么走；模型只完成其中被分配的任务。
- Agent：给模型一个目标，由模型自己判断下一步做什么、调用什么工具、是否重试以及什么时候结束。

## 生活类比

### Workflow 像固定体检流程

```text
登记
→ 测血压
→ 抽血
→ 医生查看报告
→ 输出结论
```

每一步提前确定，执行者不能自由改变流程。

### Agent 像一个被交代任务的助理

```text
目标：帮我查清身体不适的可能原因
```

助理可能自己决定：

- 先问症状；
- 再查资料；
- 决定调用哪个工具；
- 发现信息不足后继续追问；
- 根据中间结果改变下一步。

它的行动路径不是产品经理提前完全写死的。

## ReadMatch v1 的任务是否需要模型自己规划

当前链路已经明确：

```text
读取用户选择
→ 定位指定书籍
→ 检索相关证据
→ 归纳匹配点和风险
→ 规则校验
→ 输出结果
```

系统不需要让模型自己决定：

- 去哪个网站搜索；
- 调用多少种工具；
- 是否自动购买或阅读小说；
- 是否创建新的子任务；
- 是否反复自主搜索直到满意。

因此固定 Workflow 已经足够。

## 如果强行使用 Agent 会增加什么

- 路径不稳定：同样输入可能执行不同步骤；
- 难评测：无法只比较一个固定链路；
- 成本增加：可能多次调用模型和工具；
- 延迟增加：需要多轮思考和执行；
- 错误面扩大：可能调用错误工具、重复搜索或引用错误来源；
- 开发范围扩大：需要工具权限、状态管理、停止条件和异常恢复。

这些成本没有给 ReadMatch v1 带来足够新增价值。

## 什么时候 ReadMatch 未来可能需要 Agent

例如未来开放以下任务：

> 用户输入一本到书，系统自主前往多个合法数据源搜索官方信息、书评和避雷内容，发现证据冲突后继续寻找来源，最后生成报告。

这时步骤无法完全预先确定，模型需要动态选择工具、判断信息是否充分并决定是否继续检索，才可能使用 Agent。

但这涉及平台权限、版权、隐私、成本、来源可信度和复杂评测，不属于一个月 MVP。

## 面试回答模板

不要机械背诵，理解后用自己的话表达：

> ReadMatch 第一版没有使用 Agent，因为用户任务和数据流是确定的：系统定位用户指定作品，检索受控证据，由大模型完成观点归纳和个性化比较，再通过规则校验事实、雷点和引用。固定 Workflow 更稳定、成本更低，也更容易建立回归评测。只有未来需要模型自主选择多个外部数据源、根据中间结果决定下一步并多轮检索时，才会考虑 Agent。
