## 一、实验目的

使用同一组真实作品和用户条件比较：

1. 默认通用大模型；
2. 优化 Prompt 的通用大模型；
3. ReadMatch 受控证据工作流的手工模拟。

核心问题：

> ReadMatch 是否在硬性雷点逐项检查、证据支持、冲突观点、未知表达和决策可执行性上，比通用大模型聊天产生稳定优势？

## 三、Case 设计规则

每本书建立 2 个 Case：

### Case A：正向偏好

用户希望某种体验，测试系统能否：

- 识别匹配点；
- 给出证据；
- 不夸大；
- 同时提示可能冲突。

### Case B：硬性雷点或证据不足

用户设置一个可能存在、存在争议或难以确认的条件，测试系统能否：

- 逐项检查；
- 不遗漏；
- 有证据才判断；
- 没有证据时标记未知；
- 不把“未提及”写成“不存在”。

## 五、项目负责人本轮只需提供的信息

不需要写完整评测答案。每本书只回答两句话：

```text
书名：
A 正向场景：适合想看……的用户
B 雷点/未知场景：不能接受……的用户需要重点核验
```

示例格式，不代表真实作品结论：

```text
《示例书》
A：适合想看双强、剧情推进快的用户。
B：不能接受长期误会的用户需要重点核验。
```

## 六、完成用户场景后的助手任务

1. 将 10 个 Case 转成统一输入；
2. 为方案 A 和 B 编写公平 Prompt；
3. 建立 ReadMatch 手工模拟输出模板；
4. 列出每个 Case 需要收集的最小证据；
5. 不替项目负责人编造作品评价或预期结论；
6. 用户确认后再执行 Baseline 对比。

## 七、用户场景身份说明

本实验中的 A/B 条件是目标读者画像和待验证需求，不代表项目负责人个人不能接受或一定会选择排除某类作品。执行实验时，输入应写成：

```text
某类读者希望核验……
某类读者可能避开……
```

而不是默认写成项目负责人的个人偏好。
