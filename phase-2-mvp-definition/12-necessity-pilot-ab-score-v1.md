## 三、CASE-001B《撒野》评分

### Gold Label 基线

- 互攻/攻受位不明确：`present`，官方页面标注互攻视角；
- 校园背景：`present`，官方简介标注校园文；
- 主角家庭经济困境：`possible`，多个来源支持家庭和生活压力，但“穷/明显经济困境”的阈值具有主观性。

### OUT-SZ-A｜默认自然提问

#### 输出摘要

直接判断“不适合”，逐项提到互攻、校园和家庭/经济环境，给出一个晋江链接。

#### 评分

| 维度 | 分数 | 理由 |
|---|---:|---|
| 条件覆盖 | 2 | 三个条件均被提及 |
| 事实正确 | 2 | 互攻和校园方向正确，家庭困境方向基本有依据 |
| 证据支持 | 1 | 仅提供一个来源，无法清晰追溯每个结论 |
| 未知校准 | 0 | 将家庭经济困境直接写成确定雷点，未说明“穷”的阈值 |
| 观点分层 | 0 | 官方事实、读者观点和归纳混在一起 |
| 剧透控制 | 2 | 未展开重大后期剧透 |
| 决策可执行 | 2 | 明确给出排除建议 |
| **总分** | **9/14** | 结果简洁，但缺乏分层和未知校准 |

#### 风险

- `overgeneralization`：从家庭和环境压力扩展为整体“贫困小城生存困境”；
- `source_coverage_low`：链接不能逐条支撑全部结论；
- 暂不记为确定 P0，但进入“无证据程度判断”复核项。

|---|---:|---|
| 条件覆盖 | 2 | 三个条件均逐项检查 |
| 事实正确 | 2 | 互攻和校园与官方来源一致 |
| 证据支持 | 2 | 能把官方、读者评论和归纳分层 |
| 未知校准 | 0 | 仍将“明显经济困境”标为已确认存在，未保留阈值差异 |
| 观点分层 | 2 | 分层明显优于默认回答 |
| 剧透控制 | 2 | 提前说明轻微剧透且未展开重大结局 |
| 决策可执行 | 2 | 行动与两个已确认硬条件一致 |
| **总分** | **12/14** | 结构和来源显著改善，但优化 Prompt 未解决程度型标签过度确定 |

#### 风险

- `unknown_calibration_error`：Gold Label 为 possible，输出却标记 confirmed；

## 四、CASE-004B《囚于永夜》评分

### Gold Label 修订

- ABO：`present`，官方页面明确 beta、omega、高匹配度等设定；
- 攻虐受：不能作为单一二元标签。具体身体/情感/控制伤害存在部分证据，但责任归属、强度和持续性需要 `possible/conflicting`；
- 死盾梗：证据支持“被认为死亡但实际生还”的效果；是否符合用户定义的“角色主动假死推动剧情”需要进一步核验，因此由原 `present_with_medium_evidence` 修订为 `possible`。

修订理由：预测试输出暴露了“被认为死亡/死里逃生”和“角色主动策划假死”并非同一概念，Gold Label 必须遵守用户定义。

### OUT-QY-A｜默认自然提问

#### 输出摘要

直接判断不适合，分别说明 ABO、攻虐受观感和假死/死遁式分离，并展开了后期爆炸、被认为死亡和实际存活。

#### 评分

| 维度 | 分数 | 理由 |
|---|---:|---|
| 条件覆盖 | 2 | 三个条件均涉及 |
| 事实正确 | 1 | ABO 正确；“攻虐受”和“死盾”使用了宽泛定义 |
| 证据支持 | 1 | 有来源，但没有逐层说明来源性质和强度 |
| 未知校准 | 0 | 将严格死盾定义与死里逃生效果混同并直接判定 |
| 观点分层 | 1 | 使用“观感”保留部分主观性，但仍混合事实和判断 |
| 剧透控制 | 0 | 未警告即展开关键后期生死信息 |
| 决策可执行 | 2 | 明确给出排除建议 |
| **总分** | **7/14** | 简洁但存在重大剧透和定义漂移 |

#### P0

- `major_spoiler_exposed`；
- `definition_mismatch`：把“假死效果/死里逃生”直接等同于用户定义的主动死盾。

### OUT-QY-B｜优化 Prompt

#### 输出摘要

逐项拆分 ABO、身体伤害、情感伤害、控制、权力压迫、长期后果和假死，并区分部分事实、观点冲突和归责问题。答案非常长，且后半部分重复了一次核心内容。

#### 评分

| 维度 | 分数 | 理由 |
|---|---:|---|
| 条件覆盖 | 2 | 所有条件和伤害子类型均被检查 |
| 事实正确 | 1 | 多数基础方向合理，但混用官方、第三方转载和读者总结，且部分归责仍过度 |
| 证据支持 | 2 | 引用来源数量多，并尝试区分来源性质 |
| 未知校准 | 1 | 文中承认严格死盾和部分伤害归责不能确认，但顶部仍标记“已确认存在”，前后不一致 |
| 观点分层 | 2 | 能区分事实、读者观点和归纳 |
| 剧透控制 | 0 | 虽称不展开，却大量描述章节、身体伤害和后期生死细节 |
| 决策可执行 | 1 | 最终动作明确，但信息过载且存在重复，用户难以快速判断 |
| **总分** | **9/14** | 分析深度提高，但用户体验、安全和结论一致性没有同步提高 |

#### P0

- `major_spoiler_exposed`；
- `unsupported_certainty`：顶部将严格死盾标记 confirmed，正文又承认主动策划无法确认；
- `source_quality_mixed`：使用非官方转载/聚合来源支持关键剧情；
- 如果重复段落属于原始输出，则增加 `response_duplication` 系统质量问题。

## 五、A/B 初步发现

### 优化 Prompt 确实改善

- 条件覆盖；
- 输出结构；
- 事实/观点分层；
- 来源数量；
- 对复合雷点的拆解。

### 优化 Prompt 没有自动解决

- 程度型标签的过度确定；
- 顶部结论与正文边界不一致；
- 来源可信等级混用；
- 重大剧透；
- 过长和重复；
- 用户是否真的需要如此复杂的答案。

### 对产品假设的影响

目前已经观察到一个值得继续验证的差异空间：

> ReadMatch 的潜在价值可能不只是“写出结构化 Prompt”，而是固定证据等级、统一领域定义、强制未知校准、剧透控制和短结果层级。

但该价值尚未通过方案 C 和用户行为证明。
